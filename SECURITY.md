# Reporting a security issue

Use **Security → Report a vulnerability** on this repository when private reporting is available. If that option is unavailable, ask a maintainer for a private reporting channel before sending details. Keep personal scan evidence, file paths, addresses, and browser records out of public issues.

Include the affected version or commit, the selected scan mode, the expected behavior, and steps that reproduce the issue with synthetic data. Relevant issues include unintended network access, disclosure of evidence through a filtered summary, access to an excluded artifact, and a coverage gap reported as a successful check.

For an inaccurate indicator, identify the public feed entry and its source. For a suspected infection on your own device, see the investigation guidance in the [README](README.md). For build and release verification, see [Verifying a release](docs/VERIFYING.md).
