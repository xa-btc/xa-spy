# Windows coverage and upstream comparison

This matrix describes the native Windows audit, not complete upstream parity. Inventory is evidence of a current registration/record, not a compromise finding. Indicators are compared where applicable; discovered supported binaries are queued for the separate file-hash check. Permission/schema/bound failures are reported per check. No check proves absence of unknown malware.

| Check | Native source and behavior | Upstream relationship and limits |
| --- | --- | --- |
| Processes | Toolhelp snapshot, PID/name, accessible image path; queue supported image hashes | Adds explicit process inventory; protected/terminated processes may deny path access; no memory or arguments |
| Services | SCM enumeration/config/state, extracted executable and ServiceDll paths | Ports core service persistence coverage from traces.py; registration is not execution proof; shared-service DLL paths are candidates |
| Drivers | SCM registered kernel/filesystem driver state and paths | Adds explicit driver inventory; vulnerable-driver hashes are leads to legitimate software, not automatic malware |
| Startup registry | HKCU/HKLM Run, RunOnce and Explorer policy Run in 32/64-bit views | Ports core startup registrations; values are reduced to executable spelling and arguments omitted; unsupported spellings are gaps |
| Startup folders | Current-user and common Startup top-level entries; shortcut target via read-only COM persistence | Ports core Startup coverage; no URL-file execution, shortcut resolution, launches or argument collection |
| Scheduled tasks | Local Task Scheduler metadata and executable action paths | Ports task persistence inventory; no task XML/script/credential/argument retention; non-executable actions are marked unsupported |
| Installed applications | Both uninstall registry views under HKCU/HKLM | Adds desktop inventory; portable software and Store packages may be absent; no uninstall execution |
| Defender/security | Local MSFT_MpComputerStatus fields and SecurityCenter2 registered antivirus name/state | Provider-reported status only; no scan, settings change or guarantee. Missing namespaces/classes are unsupported; providers can delay cancellation |
| Optional Windows security settings | Remote Desktop host setting and Secure Boot state from local registry values, three Windows Firewall profile states, and BitLocker protection from the local encryption provider | Configuration observations are private. Missing permissions and unavailable providers reduce coverage. These checks do not verify network reachability or modify settings. |
| Event logs | Selected System, Defender, PowerShell, Security and CodeIntegrity system fields | Selected metadata coverage from upstream host/execution topics; last seven days, at most 1,000 events per channel; no event message/script/command content. Security log may deny ordinary users |
| Existing connections | IP Helper TCP/UDP IPv4/IPv6 rows, numeric endpoints, PID and best-effort process image | Adds explicit connection ownership; no DNS lookup, ping, remote probes or traffic capture. UDP tables describe bindings, not remote peers |
| Connected devices | Present PnP device friendly/class/manufacturer/provider and registered driver metadata | Adds device inventory; no serial/instance IDs, phone contents, USB-device reads or firmware integrity assessment |
| File hashes | SHA-256 of EXE/DLL/SYS/SCR/MSI/COM candidates from system metadata or selected folder | Retains known-sample/vulnerable-driver matching from curated text feeds; 120 MiB/file, 64 directory levels, 100,000 entries/root; no arbitrary pattern/YARA engine |
| Chromium history/downloads | Structured read-only History tables, host-only values, distinct history/download reference grades | Narrower than upstream browser reader; no raw cache/storage/favicon/HSTS/cookies or complete snapshot. History need not be local-origin contact; downloads do not establish execution |
| Firefox history | Structured read-only places.sqlite history records reduced to host | Narrower than upstream; no cookies/password stores, deleted-page recovery or open-writer snapshots |
| Chromium bookmarks | Bounded structured JSON URL nodes reduced to host | Saved reference only, never proof of visit. Empty supported stores may have no records |
| Host COM/DNS/hosts/known-path indicators | Not ported as independent checks | Upstream host.py has broader COM registration, DNS cache/log and hosts-file/known-path inspection; no implicit equivalent is claimed |
| Extended execution traces | Selected event system metadata only | Upstream has additional artifact content and correlation (execution/persistence/Defender/PowerShell). Prefetch/Amcache/Shimcache and script-content correlation are not ported |
| Additional feeds and withdrawals | Two bundled curated text feeds only, source tags retained per match | No online feed refresh, external STIX import, withdrawal processor or automatic currency verification; inspect source dates/citations before acting on a lead |
| Phone acquisition/analysis, macOS/Linux | Outside this Windows goal | Upstream contains these features; native XA Spy does not invoke them |

Collector enumeration is bounded to 10,000 steps/records per check with 4 MiB metadata buffers and bounded retained strings. Tasks additionally cap folder depth/queue/actions. Browser artifacts cap SQLite input at 120 MiB, Bookmarks at 8 MiB, records at 50,000 and work time at 15 seconds/artifact. Unsupported Unicode/IDN URL forms and incomplete/locked/sidecar databases create gaps. Current-user profile discovery is opt-in; other accounts are not silently searched.

Every emitted inventory item remains private. Only fixed module outcomes and counters reach AI. The default system check list is native/audit.hpp and systemChecks() in native/scanner.cpp; live implementation is native/windows_collectors.cpp. The isolated fixture backend supplies synthetic records through the same engine/reporting flow and never falls back to those live calls. Fixture results validate the application contract, not actual collection coverage on an unscanned Windows installation.
